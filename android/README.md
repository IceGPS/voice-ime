# 第二阶段 · Android 输入法

> ⏳ 待第一阶段（Windows）全部验收通过后启动。

## 架构

```
┌─────────────────────┐      ┌──────────────────────────────┐
│ 键盘进程             │      │ 前台 Service（推理）           │
│ InputMethodService   │      │ - Qwen3-ASR-0.6B（MNN）       │
│ + RECORD_AUDIO       │─────▶│ - silero-vad 静音断句          │
│ 键盘内直接录音       │ 音频流 │ - 常驻通知防被杀              │
│ 麦克风键 + 候选词条  │      └──────────────┬───────────────┘
└─────────────────────┘                     │ 转写文本
                                            ▼
                              InputConnection.commitText() 上屏
```

- 不需要 iOS 那套"跳主 App" workaround，安卓键盘可直接拿麦克风。
- 推理放前台 Service，不放输入法进程（输入法进程易被系统杀掉）。
- 录音：AudioRecord，16kHz 单声道。

## 与第一阶段的关系

| 复用（不动） | 重写 |
|---|---|
| 文档编译器（`../shared/`）及契约 | 音频采集（AudioRecord） |
| 语气词过滤规则 | 上屏机制（commitText） |
| 每日文档格式 | 键盘 UI |
| 日志层字段（时间戳/文本/录音路径） | 模型运行时（MNN 移植） |

手机端先按 CapsWriter 同字段落盘日志层，再复用同一文档编译器，
两端产出的每日文档结构一致。

## UI 要求

键盘内转写预览/编辑区同样随内容自动增高（见 `docs/plan.md`），
设最大高度、超出后区域内滚动。
