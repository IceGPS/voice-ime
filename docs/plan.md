# 项目计划（精简版）

完整版见《语音输入法项目实施文档》v1.3（PDF）。

## 目标

1. 本地离线语音识别（Qwen3-ASR），不依赖网络。
2. 每天的输入自动整理成一篇 Markdown 文档。

## 两层结构

| 层 | 内容 | 状态 |
|---|---|---|
| 日志层 | 录音 + 原始转写（含语气词、带时间戳） | CapsWriter 已有，只验证 |
| 文档层 | 当天转写 → 整理成一篇可读文档 | **本项目重点开发** |

## 文档编译流水线

```
读取 → 清洗 → 分组 → 成文 → 修订保护
```

- **读取**：取当天日志层全部条目（按时间排序）。
- **清洗**：标点恢复 → 分句 → 语气词过滤（删句首"嗯/呃/那个"及重复堆叠；
  留句尾语气"吧/呢/啊"、感叹"啊"、问答应答"嗯"；规则先行，歧义项用小模型判别）。
  不在 ASR 解码阶段压制语气词，保护时间戳对齐。
- **分组**：按时间段 / 主题聚类，合并碎片句子。
- **成文**：去口语化，输出 `docs/daily/YYYY-MM-DD.md`。
- **修订保护**：人工修改过的段落，重跑时不覆盖（幂等）。

触发：随时手动预览 / 日终自动出稿 / 增量重编。

## 模型选型

| 端 | 模型 | 说明 |
|---|---|---|
| Windows | Qwen3-ASR-1.7B（GGUF，Vulkan 加速，约 1.6GB 显存） | 准确率优先 |
| Android | Qwen3-ASR-0.6B（约 860MB）起步 | 先打通链路，视手机性能再上 1.7B |
| 保底 | FunASR Paraformer（sherpa-onnx，有现成 Android demo） | Qwen 移植困难时启用 |

## UI 要求（两端共用）

转写编辑区必须随内容行数自动增高（对标 Muse app 输入框），
设最大高度、超出后内部滚动、光标行始终可见；
禁止固定高度导致"只能看见最前几个字"（反例：Grok Bot app）。
